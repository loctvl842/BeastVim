packer-install-failure

Wrap vim.pack.add so a failed clone no longer aborts setup. Record failures in a small JSON file, skip known-broken plugins until a retry window expires, and show/retry them in the Packer window.

How setup changes

Problem: vim.pack.add throws after installing the others and the failure branch returns (init.lua:383-396), skipping Step 5. Nothing is remembered, so each start re-clones (~300ms/plugin, 824ms measured for one bogus repo).

Research

  • Searched: vim.pack.add, installed_plugins, stdpath("state"/"cache"), Toast(, operation., PackChanged.
  • Found: single vim.pack.add call; state data goes under stdpath("state") (session lib); UI lists only installed plugins; no existing failure persistence; no packer test file.
  • Measured: good plugin installs, then the call throws (Neovim 0.12.6). No "skip failures" option, so filter specs first. Use fs_stat on the opt dir, not vim.pack.get() (git per plugin).
  • Decision: Reuse Toast / operation / UI action patterns; Build one small module.
Verify first: when vim.pack.add throws, does it still call the load callback for the plugins that installed? If not, setup must load the eager ones itself. Phase 1 step 1 is a headless probe.

PM spec gap

The PM spec says "install/sync action in the Packer window". No such action exists today (only Load, Sort, Delete, Update, Filter, Group, Profile, Help, Close), and update does not install a never-installed plugin. This plan adds a dedicated Retry key (r). Recommended: change the PM spec wording from "install/sync" to "retry".

Phases

Phase 1 · Setup survives a failure smallest slice
  1. Probe vim.pack.add failure behavior (scratch). Risk low.
  2. Add failures.lua, in-memory API. Low.
  3. Stop aborting on throw in init.lua: record missing specs, load installed eager plugins if needed, one combined Toast, fall through to Step 5. Medium: load vs config ordering.
  4. state.load skips failed plugins so lazy triggers do not raise. Low.
Phase 2 · Remember across starts depends on 1
  1. Persist JSON under stdpath("state"); corrupt or missing file = empty. Low.
  2. Filter before vim.pack.add: drop only if missing on disk + same src + age < window. Prune stale records. Medium: never skip an installed spec.
  3. install_retry_hours = 24 option. Low.
  4. Retry that fails again: re-record, Toast once. Low.
Phase 3 · Show and retry in the Packer window depends on 2
  1. "Failed" section with reason and age. Low.
  2. r retry action: clear record, vim.pack.add({spec}) in pcall, Toast result. Medium.
  3. Health check warns per recorded failure. Low.
  4. Failure notices via Toast; other vim.notify calls untouched. Low.

Testing

  • Headless: new tests/test-packer-failures.lua (round trip, corrupt file, window expiry, changed src, installed never blocked, combined names).
  • Bench: ./scripts/bench-startup.sh with a recorded failure must not be slower than baseline.
  • Manual: PM scenarios 1-6 in a scratch NVIM_APPNAME with one bogus GitHub spec; scenario 3 via r.
  • E2E first: reproduce the abort with a nonexistent repo, then confirm the fix.

Success criteria

  • Other plugins still load and configure with one unreachable plugin.
  • One toast on first start; none inside the window.
  • No startup slowdown from a known-broken plugin.
  • Packer window lists it with reason and age; r retries and clears on success.
  • Several failures give one combined toast; no raw error message.
  • Corrupt or missing failures file never breaks startup.
  • Unit tests pass; startup bench shows no regression.
