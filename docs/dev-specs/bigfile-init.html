Big file lib

A new bigfile lib answers one question, "is this buffer big, and is feature X off for it?". Each costly lib gets one early-return guard that asks it. The lib decides lazily (so autocmd order does not matter), remembers the answer per buffer, and shows one Toast per open.

PM spec: docs/pm-specs/bigfile-init.md (approved). Sample: realistic_orders_120k.xml, 7.4 MB.

How it works

Libs never talk to each other. The hub is the only shared piece. Green boxes are owned by the new lib itself.

Context

Treesitter, LSP, git, symbols, scroll, the statuscolumn and the guides' scope search all run per redraw, cursor move or edit, so a 121k-line file pays for all of them on every key. Each lib has its own exclusion point but none looks at size.

After this change one lib owns the definition of "big" and the list of switched-off features, and each lib asks at its existing exclusion point. The filetype is untouched.

Research

Searched: bigfile, max_filesize, per-buffer disable flags, notice mechanisms, lib conventions, Neovim 0.12 LSP enable internals.

Found: no size logic anywhere. Scroll already has vim.b.beast_scroll_disabled. Every other lib has an exclusion function to extend. Notices go through Toast.

Rejected: vim.filetype.add like snacks (loses the xml filetype); an autocmd-set flag (races treesitter's FileType handler).

Decision: Build small lib, Reuse each lib's existing exclusion point, window options and Toast.

feature: treesitter indent lsp git breadcrumb scroll matchparen fold conceal signs

Big = real file buffer, loaded, size over 1.5 MB, or average line over 1,000 characters. An unloaded buffer answers false and is not remembered.

Phases

Phase 1: Classifier and notice risk: medium

Goal: the lib exists, nothing consumes it yet. Mergeable alone.

  1. Config (bigfile/config.lua): enabled, notify, size, line_length, disable table (all true).
  2. Classifier (bigfile/init.lua): lazy is, memo cleared on unload and wipeout.
  3. Notice and wiring (bigfile/init.lua, lua/beast/init.lua): one Toast per open; setup is eager because nvim file fires FileType before any deferred event. Check Toast works that early.

Phase 2: Cheap guards risk: low

Goal: treesitter, indent, scroll honor the flag. Depends on phase 1.

  1. Treesitter: early return in start_buf; context can_show false.
  2. Indent guides: stay on (disable.indent = false). For a big buffer scope.find skips the treesitter strategy (it parses the whole file) and caps the indent walk at 1000 lines each way.
  3. Scroll: buf_disabled also asks the lib.

Phase 3: Background workers risk: high (LSP)

Goal: no server, no git, no symbol requests for the big buffer. Depends on phase 1.

  1. LSP: wrap root_dir in register so no on_dir call means no start; LspAttach detaches this buffer as a backstop. Servers shared with other buffers keep serving them.
  2. Git: buffer_eligible false.
  3. Breadcrumb symbols: empty trail, no refresh; the file path part stays.

Phase 4: Window-local behavior risk: medium

Goal: folds, conceal, matchparen and gutter. Depends on phase 1.

  1. Window options (bigfile/window.lua): on BufWinEnter of a big buffer save foldmethod and conceallevel in vim.w and set manual and 0; restore when the window shows another buffer. Matchparen: empty buffer-local matchpairs (verify).
  2. Statuscolumn: number producer only; the check must be a table lookup.
  3. Syntax gate: confirm regex coloring stays responsive on the sample; if not, add synmaxcol through the same mechanism.

Phase 5: Verify, bench, document risk: low

  1. Specs for the classifier and each guard.
  2. New bench-bigfile.lua, plus bench-startup.sh and bench-ux.sh all (setup is eager, normal files must not regress).
  3. /update-codemap.

Decisions for you

How to keep the language server off a big file

Recommended: wrap root_dir in Lsp.register (server never starts), plus detach this buffer in LspAttach as a backstop. Neovim 0.12 starts a client only when on_dir is called.
Only detach in LspAttach. Simpler, but the server process still starts and may index the file first.

How libs learn the verdict

Recommended: libs call Bigfile.disabled(buf, feature), which decides lazily and memoizes. No ordering dependency.
An autocmd sets vim.b.beast_bigfile. Racy: filetypedetect runs on BufRead, so treesitter's FileType handler can run first.

The 7.4 MB fixture

Recommended: do not commit realistic_orders_120k.xml; generate a similar file inside the bench and tests.
Commit it. Adds 7.4 MB to the repository.

Testing strategy

  • Specs (make test): small, over-size, minified, new/empty, non-file buffer, not-yet-loaded, enabled = false, per-feature disable, survives :e, one Toast per open (stubbed recorder), filetype still xml; one guard spec per touched lib; split with big and normal buffers keeps window options separate.
  • Bench: new bench-bigfile.lua; bench-startup.sh; bench-ux.sh all.
  • Manual: the seven PM scenarios, with scenario 1 launched straight from the shell to cover the startup path.
  • Gates: lua-language-server --check at Warning level and stylua clean.

Success criteria

  • One "Big File" toast with name and size on open, including from the shell.
  • j, Ctrl-D, G and typing feel instant on the sample.
  • No treesitter, context, LSP client, git signs or symbol trail in that buffer; indent guides and scope still shown.
  • Line numbers, regex coloring, search, search count, undo and statusline still work.
  • A minified 900 KB file behaves the same.
  • A small file, even in a split next to the big one, keeps every feature.
  • Filetype of the big file is still xml.
  • notify = false silences the toast; disable.<feature> = false keeps that feature.
  • Reopening shows the toast once per open.
  • make test, type check and stylua clean; no startup regression.
