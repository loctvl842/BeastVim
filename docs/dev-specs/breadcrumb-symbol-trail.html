Dev spec / breadcrumb

Symbol Trail

PM spec: docs/pm-specs/breadcrumb-symbol-trail.md

TL;DR: add a symbols/ submodule to the breadcrumb lib. It returns the chain of {name, kind} at a window's cursor, from LSP documentSymbol when a server answers, else from a treesitter ancestor walk. filepath.lua renders it with kind icons and a new truncation order. No new plugin, no new global, one new config key: symbols.

What is missing in the code

  • filepath.render draws path + file + marker only. The "code context" in breadcrumb-init was never built.
  • Nothing in the repo requests documentSymbol.
  • The cache reacts to buffer / name / modified only, never to cursor movement.
  • Truncation only knows about directories.

How it works

Cache hit returns the stored string, so moving the cursor never recomputes anything until it has been still for 60 ms.

Research

Searched / found

  • No existing documentSymbol consumer. One precedent for the request shape: finder/source/lsp.lua (buf_request_all).
  • Icon.kinds already has every LSP symbol kind name.
  • Lsp.on_attach exists and runs after per-server handlers.
  • Treesitter context.scm has header ranges only (no names/kinds). locals.scm is on 14 languages and gives identifiers, not ranges. So the fallback needs its own tiny per-language node table.

Decision: Reuse + Build. Reuse platform APIs and breadcrumb scaffolding; build store, kind table, node table, render changes. nvim-navic is not used.

Phases

Phase 1: Render a trail risk: medium

Goal: given a symbol list, the bar renders and truncates correctly. Nothing supplies symbols yet, so the bar is unchanged.

  1. config.lua: symbols = true.
  2. symbols/kinds.lua: kind number to Icon.kinds key; families Callable / Type / Module / Value.
  3. highlights.lua: Symbol, SymCallable, SymType, SymModule, SymValue from the treesitter palette.
  4. filepath.lua: new signature, symbol segments, one shared drop_left helper (dirs first, then symbols, innermost kept, ... after file), marker appended last. Output with no symbols must match today's.
  5. tests/test-breadcrumb-symbols.lua: truncation stages, marker position, no-symbol parity; visual check in light and dark.

Depends on: none.

Phase 2: LSP source risk: high

Goal: language-server files get a live trail; others unchanged.

  1. symbols/lsp.lua: per-buffer {tree, seq}, refresh, normalize both response shapes, find(tree, row, col), clear. Empty or errored reply keeps the old tree.
  2. symbols/init.lua: trail(bufnr, winid) using the window's own cursor.
  3. init.lua: call trail on cache miss; LspAttach autocmd (not Lsp.on_attach, which cannot be unsubscribed), LspDetach, LspProgress end, TextChanged(I), InsertLeave, BufEnter, BufDelete; cursor (60 ms) and refresh (300 ms) timers; all inside the existing augroup; skipped when symbols = false; setup() resets the timer.
  4. Tests: lookup (nested, siblings, header line, between, outside), normalization, out-of-order replies, empty reply.

Depends on: Phase 1 step 2. Risk is event ordering, timer lifetime, redraw storms.

Phase 3: Treesitter fallback risk: medium

Goal: files with a parser but no server get a trail with the same look.

  1. symbols/treesitter.lua: get_node + :parent() walk; v1 languages: lua, python, javascript, typescript, tsx, c, cpp, go, rust, markdown. Node names verified against installed parsers by tests.
  2. symbols/init.lua: fall back when the LSP tree is empty; never concatenate.
  3. init.lua: add FileType to buffer invalidation; edits invalidate when treesitter is the active source.
  4. Fixtures per language; uninstalled parser prints SKIP. Markdown fixture has a fenced block; Lua fixture has an anonymous callback.

Depends on: Phase 1 step 2.

Phase 4: Health, bench, docs risk: low

  1. health.lua: load checks, symbols toggle, LSP clients with documentSymbol, treesitter coverage for the filetype.
  2. bench-breadcrumb.lua: find on 5k symbols depth 6; cache-miss render with a 5-symbol trail; cache-hit must not regress.
  3. Codemap via /update-codemap. No hand edits, no CHANGELOG.md.

Depends on: Phases 2-3.

Testing strategy

  • Headless: nvim --clean --headless -l tests/test-breadcrumb-symbols.lua
  • Bench (mandatory): bench-breadcrumb.lua, bench-startup.sh, and bench-ux.sh all because new cursor autocmds touch input-to-paint latency.
  • Types: lua-language-server --check at Warning level.
  • Manual E2E (real editor, NVIM_APPNAME=BeastVim, via tmux), one pass per PM scenario: walk a file, cold-start on a big file, type/add/rename, :vsplit, shrink the window, symbols = false, markdown vs plain text, hold j. Check every state pixel by pixel in light and dark.

Success criteria

  • Cursor in a function / method / class shows its name with a kind icon after the file name.
  • Nested symbols show outermost first; outside any symbol shows file only.
  • Two windows on one file show independent trails.
  • Trail appears by itself once a slow server is ready; typing never blanks it.
  • Truncation order: dirs, then outer symbols; file, innermost symbol and marker kept; marker last.
  • No server but a known language: same-look trail. Server wins when both exist; sources never mix.
  • Plain text and unknown languages look as today.
  • symbols = false restores today's bar and issues no documentSymbol request.
  • No stutter holding j / k.
  • Gates: new test passes, breadcrumb bench passes with cache-hit time unchanged, bench-ux.sh all no regression, type check clean, no vim.notify, no lib keymaps.
