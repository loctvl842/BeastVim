git-remote

New libs/git/remote.lua reads a project's git remotes and answers Git.providers(), Git.has_provider(name) and Git.remote(provider). Git becomes a global. The startup keys and the finder's GitHub source delegate to it, so no other lib defines remote logic. Groundwork for refactoring the lazy provider keys next.

No PM spec: not a UI feature.

The problem

sync_gh_keys spawns git remote get-url origin, parses it with the finder's parser, and tests host:find("github"). The parser and a second origin lookup live in the finder, the provider test in the startup file, and GitLab or a second remote cannot be asked about at all.

After the change

Result for a repo with origin on GitHub and mirror on GitLab: providers() is { "github", "gitlab" }, has_provider("bitbucket") is false.

Research

Found: parse_remote in finder/source/gh/api.lua (tested), the inline host test in sync_gh_keys, nothing remote-aware in libs/git. git config --get-regexp lists all remotes in one process.

Decision: Reuse the parser (moved, then deleted from the finder), Build remote.lua. Finder tests that mock the origin command are updated.

Decisions for you

D1 · RECOMMENDED
Sync, cached per root. Matches the requested return shape; one ~3 ms spawn per root per session.
Alternative: async refresh(root, cb); has_provider would be wrong until the callback fires.
D2 · RECOMMENDED
All remotes count. Needed to produce { "github", "gitlab" }.
Alternative: origin only.
D3 · RECOMMENDED
Substring rule on the host (github, gitlab); keeps GitHub Enterprise working, same as today.
Alternative: exact hosts.
D4 · CONFIRMED IN REVIEW
_G.Git = Util.mod("beast.libs.git") next to Key/View. It loads the lib file at startup, so the startup bench gates it; if it regresses, make the lib's internal requires lazy.
D6 · CONFIRMED IN REVIEW
Finder keeps no parse_remote. gh/api.lua uses Git.remote("github", cwd). One parser, one place to fix bugs.
D7 · RECOMMENDED
Config map for custom hosts: remote = { hosts = { ["git.acme.dev"] = "github" } }, empty by default. The finder used to accept any host gh was logged into; without this, such enterprise hosts would be dropped.
Alternative: accept the regression.
D5 · RECOMMENDED
invalidate() plus a FocusGained hook, so a git remote add in another terminal shows up.
Alternative: never invalidate.

Phases

Phase 1: remote module · risk medium · depends on nothing
  1. Move the parser into remote.parse.
  2. provider_of(host) and list(root) via git config --get-regexp.
  3. providers, has_provider, remote(provider), per-root cache, invalidate, one-time FocusGained autocmd, config.remote.hosts.
  4. Public functions in libs/git/init.lua and _G.Git in lua/beast/init.lua; run the startup bench.
  5. tests/test-git-remote.lua with a stubbed vim.system.
Phase 2: consumers · risk medium · depends on Phase 1
  1. Delete the finder's parse_remote; repo() returns Git.remote("github", cwd); update the finder tests' mocks.
  2. sync_gh_keys drops the spawn, parse and host test; keeps the root short-circuit, gh_keys_set guard and Key calls. First BufEnter in a new root blocks for one spawn, so check the startup bench.

Testing

  • New tests/test-git-remote.lua; re-run every tests/test-finder-gh-*.lua, updating mocks of the origin command.
  • ./scripts/bench-startup.sh before and after Phase 2; type check with lua-language-server.
  • Manual: GitHub repo shows <leader>ghp/ghi; :cd to a non-GitHub dir removes them; add a GitLab mirror remote and print providers().
