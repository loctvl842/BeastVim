Stable theme menu - implementation

Copy every picker highlight into two window-local namespaces at open time (prompt panel, list panel) and attach them with nvim_win_set_hl_ns. Live preview rewrites only global highlights, so the menu keeps its colors. The backdrop becomes opt-out.

PM spec: docs/pm-specs/finder-colorscheme-stable-menu.md

Why this works

Spike result (real nvim, tmux): a float with nvim_win_set_hl_ns kept its ns-defined Normal, FloatBorder and extmark colors while :colorscheme flipped the editor from dark to light. winhl mappings do not resolve through the namespace, so base groups are defined directly in it.

Research

Backdrop is created unconditionally and relayout calls it unguarded. Panel colors flow through winhl to groups built by highlights.get() and rebuilt by hl_reload on every ColorScheme. Decision: Reuse highlights.get() as the snapshot source; Build freeze() and opt-in plumbing.

Phases

Phase 1 - Optional backdrop

  1. Skip the overlay when backdrop == false, guard relayout Low
  2. Pass it from the mapping Low

Phase 2 - Frozen colors

  1. freeze(): copy groups + Normal/NormalFloat/FloatBorder/EndOfBuffer per panel Medium (any uncopied group falls back to the previewed theme)
  2. Attach to input and list windows before first render Medium
  3. Remove winhl and the swatch reset hook Low
  4. Pass freeze_colors from the mapping Low
  5. Test: values stable across :colorscheme Low

Testing

  • Headless: new test plus all tests/test-finder-*.lua.
  • Manual in tmux: compare numeric panel colors across dark to light previews (prompt, list, lines, pointer, match highlight, empty cells), Enter and reopen, Esc restore.

Success criteria

  • ☐ Menu colors constant across previews
  • ☐ No overlay for the theme picker; others keep theirs
  • ☐ Enter then reopen shows the new theme in the menu
  • ☐ Esc restores
  • ☐ Tests green, stylua clean
