Git branch chain

Add one new picker source, git_branches, and one new level source, git_branch_files, and wire three chain edges: git_branches|git_branch_files (<C-g>), git_branches|git_commits (<C-t>) and git_branch_files|live_grep (<C-g>). Everything past the branch level (commits, a commit's files, the grep) reuses the local-commit sources. The new git reads (branch list, merge-base, branch diff, commit range) go into source/git/log.lua, in the same shapes the commit sources already consume.

PM spec: docs/pm-specs/finder-git-branch-chain.md

How the pieces connect

Context

Problem

The finder can chain local commits to their files and then to a grep (git_commits > git_commit_files > live_grep), but nothing starts from a branch: there is no branch list, no way to ask "what did this branch change against main", and git_commits can only show the whole history, not the commits of one branch.

Solution

git_branches lists local branches as commit-like items (the tip commit fields plus name/current). Its <C-t> edge opens git_commits with ctx.branch, which then lists the range merge-base..branch (or the latest 500 when the branch has nothing of its own). Its <C-g> edge is a waiting edge: it resolves the merge-base, then opens git_branch_files, which lists git diff merge-base tip through the same row builder as git_commit_files. A commit-shaped item with base set lets commit_preview.detail serve both a commit and a branch diff, so previews, caching and Enter keep working unchanged.

Decisions to confirm

Key for the branch list: <leader>gr (Recommended). The PM spec proposed <leader>gb, but it is the existing "Blame current line" key and <leader>gB is "Blame file". The PM spec is updated to match.
Titles after a branch. The PM spec writes 3 Files in <name> › Live Grep; the existing local-commit grep reads <commit> › 3 Files › Live Grep. Recommended: follow the existing pattern (<name> › 3 Files › Live Grep) so every chain reads the same. Alternative: change both.
No main or master. With neither main nor master, <C-t> lists the branch's whole history and <C-g> says "No main or master branch to compare against".

Check pixel details: current-branch marker alignment, right-aligned author/age, title shortening, hint line text.

Success Criteria

  • <leader>gr lists local branches (current first, marked), each with its latest commit line, author and age; typing filters them.
  • On a branch, <C-g> lists the files it changed against the default branch with status letters, the highlighted file's diff on the right.
  • On a branch, <C-t> lists its commits newest first (only those not on main), the highlighted commit's diff on the right.
  • On a commit (from a branch or from <leader>gc), <C-g> lists the files that commit changed.
  • On a list of changed files, <C-g> greps the existing local copies; the title counts them.
  • <BS> on an empty prompt and <C-o> go back one level without searching again, restoring prompt and highlighted row.
  • A branch with no changes of its own says so on <C-g>, still lists history on <C-t>.
  • Message rows, empty lists and "no local files" never open anything and say why.
  • The hint shows <C-g> and <C-t> on a branch, <C-g> and <BS> back elsewhere.
  • <Enter> on a branch never changes the checked-out branch.
  • All finder headless tests, the bench loop and the type check pass.
