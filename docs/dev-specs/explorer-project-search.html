Explorer project search - dev spec (v2)

Search mode is a state of the explorer, not a second explorer. While searching, state.tree points at a SearchTree, a subclass of the explorer's Tree; the existing window, buffer, render, sticky, keymaps and actions run unchanged on it. Leaving search puts the real tree back. Matches come from a headless finder session. New code: one finder file and four small explorer files, plus one-line hooks.

PM spec: docs/pm-specs/explorer-project-search.md. The first implementation is kept on branch backup/explorer-search-v1 (reviewed pieces are ported, not rewritten).

How it fits together

One override makes it safe: SearchTree inherits Tree and replaces expand so it never scans the disk, it only drops children that no longer exist. It also carries the match data (positions, count) that decorate reads. tree.lua is not edited. That keeps walk, refresh, watchers and actions from re-adding files that do not match.

Pitfalls from the first attempt

  • No trailing space on the query line (the window shows it as -); the caret char is the last character.
  • Call redraw after each paint while the key loop blocks.
  • On leaving the explorer, reveal the file now open (not the search row) and schedule it out of WinLeave.
  • Restore state.tree before revealing paths in the real tree.

Research

  • Reuse: Tree, ensure_child, render.build/write, ui, sticky, actions, files.get, matcher.run: all already go through state.tree or are headless.
  • Key finding: Tree:expand is the only place children come from disk, so one subclass override there protects every path (walk, refresh, watchers, actions).
  • Rejected: filtering the real tree (touches flat/walk); a cmdline prompt (second prompt, native / regex-searches the buffer); swapping the window buffer (needed guards, broke cursor hiding).
  • Must end search first: only set_root and navigate_up (they replace state.tree).

Phases

Phase 1: Finder headless session

One callable entry point, no UI. Port from the backup branch.

  1. files.supported()
  2. finder/search.lua: stream once, re-run matcher per query, abort stale runs, limit+1 capacity for exact capped, re-run when streaming ends, ignore late callbacks after close
  3. tests/test-finder-search.lua (14 cases)

Risk: Medium: streaming / abort races   Depends on: none

Phase 2: Explorer plumbing

SearchTree, state field, render hook. Inert until used.

  1. search/tree.lua: SearchTree extends Tree; expand only prunes missing children; from_matches
  2. state.lua: mode (normal | search) + mode_state; mode.lua: registry with enter / leave / decorate, so Git or Diagnostics modes can plug in later
  3. render.lua hook + search/decorate.lua + highlight groups
  4. Tests: SearchTree ignores extra files on disk, prunes after delete; decorate output

Risk: Low   Depends on: Phase 1 (tests only)

Phase 3: Search mode

Lifecycle, prompt, keys, degradation.

  1. search/init.lua: swap state.tree, build result tree, exit / stop, WinLeave / WinClosed / visibility autocmds
  2. search/prompt.lua: key loop, repaint per key on the top line
  3. Actions + mappings; keymaps.mount skips unavailable; set_root / navigate_up call mode.leave() first
  4. Lifecycle tests incl. folder toggle, delete, create, leave-window, degraded run

Risk: Medium: key loop + repaint   Depends on: Phase 2

Phase 4: Verify, bench, docs

  1. Bench: 1000-match tree build + render + decorate under 16 ms; existing cases unchanged
  2. Manual tmux run of all PM scenarios plus actions on results
  3. Codemap

Risk: Medium: per-keystroke budget   Depends on: Phase 3
