Explorer project search - dev spec

Search mode is a self-contained folder, explorer/search/, with its own state, its own result tree and its own buffer. It starts empty and fills while you type. It is swapped into the explorer window, so the real explorer tree is never touched. Matching comes from a new headless finder/search.lua. Without it, / stays native.

PM spec: docs/pm-specs/explorer-project-search.md

How it fits together

The only changes to existing explorer code are small: two default mappings, a skip-if-unavailable check, two early-return guards (sticky and BufEnter) for "explorer window is showing another buffer", and two exports so search can reuse open/split.

Research

  • Reuse: files.get and matcher.run are already headless; render.build draws any list of nodes with the right fields; git.resolve/diagnostics.resolve stamp badges.
  • Use: vim.fn.input (+ cancelreturn, CmdlineChanged) for the prompt; nvim_win_set_buf with winfixbuf toggled for the swap.
  • Build: the finder facade and the explorer/search/ folder.
  • Watch out: sticky.refresh and the BufEnter handler assume the explorer window shows the explorer buffer; opening a result would otherwise open real folders. Hence the two guards.

Phases

Phase 1: Finder headless session

One callable entry point, no UI. Mergeable alone.

  1. Spike: prove input() + CmdlineChanged + :redraw repaint live, and buffer swap on a winfixbuf window (throwaway)
  2. files.supported()
  3. finder/search.lua: stream once, re-run matcher per query, abort stale runs, re-run when streaming ends, ignore late callbacks after close
  4. tests/test-finder-search.lua

Risk: Medium: streaming and abort races   Depends on: none

Phase 2: Search tree and view

Self-contained, driven programmatically.

  1. search/state.lua + search/tree.lua: own nodes, git/diagnostic stamps, match positions
  2. search/view.lua: swap buffer in/out of the explorer window; close on explorer WinClosed
  3. search/render.lua: reuse render.build, rewrite header, badge, empty row, match letters
  4. Two guards in sticky.lua / autocmds.lua + highlight groups
  5. search/init.lua: start, set_query, exit, stop, visibility refresh
  6. tests/test-explorer-search.lua

Risk: Medium: render and view swap   Depends on: Phase 1

Phase 3: Prompt, keys, degradation

The user-visible feature.

  1. search/prompt.lua with debounced live updates
  2. search/keymaps.lua: <CR>, s, o, H, /, ?, <Esc><Esc>
  3. actions/search.lua + default mappings + skip-unavailable in keymaps.mount
  4. Export open/split; wire-up test incl. finder-missing

Risk: High: cmdline + redraw (spike mitigates)   Depends on: Phase 2

Phase 4: Performance and docs

  1. Bench case for build + render of 1000 matches; existing explorer cases unchanged
  2. /update-codemap

Risk: Medium: bench must show no regression   Depends on: Phase 3

Testing

  • Headless: new tests/test-finder-search.lua, tests/test-explorer-search.lua; re-run existing explorer/finder/visibility tests.
  • Bench: scripts/bench-explorer.lua with a new build+render case; UX bench after Phase 3.
  • Manual: PM scenarios 1-6, sticky absent and back, resize, close and reopen while searching, real tree unchanged after exit, pixel check of header and badge on light and dark.
