Theme picker swatches - implementation

Add a ten-color palette strip to every row of the colorschemes picker, with separator lines and a two-box card layout. Colors are read by a headless Neovim child and cached on disk, so opening the picker never repaints your editor. Picker behavior is untouched.

PM spec: docs/pm-specs/finder-colorscheme-swatches.md

How it fits together

Research

Found: ui/list.lua already has non-match "header" rows with cursor snapping (reuse for separators); theme/sources/plugin.lua maps highlight groups to palette slots; :colorscheme clears all highlights and fires hooks, so in-process scanning would flash the editor.
Decision: Reuse list row machinery; Build worker + cache; Use built-in extmark virt_text and vim.system.

Phases

Phase 1 - Swatch data (no visible change)

  1. Worker reads Normal/Diagnostic/String/Function/Keyword/Comment... into 10 colors Medium
  2. Cache + spawner, mtime invalidation Medium
  3. Attach to items Low
  4. Test: worker output, cache hit/stale, broken theme Low

Phase 2 - List rendering

  1. Multi-chunk right-aligned virt_text Low
  2. Separator rows between items, none above first / below last Medium
  3. Highlight groups: separator, empty swatch, lazy per-hex swatch Low
  4. Test: visible count, row to item mapping, scrolling Low

Phase 3 - Card layout and wiring

  1. "cards" layout: two bordered boxes, narrow, centered Low
  2. Plumb layout/separators through state, init, relayout Medium
  3. Row format: truncate name, ten squares, dim grey for missing Medium
  4. Swatches survive live preview (re-define on ColorScheme) Medium
  5. Pass options from <leader>c Low

Decisions for you

Color source - recommended
Headless child + JSON cache. Instant when warm, no editor flash.
Alternative: apply each theme in-process (flashes, blocks UI, fires hooks).
Role mapping - recommended
Fixed syntax groups: Number=orange, String=green, Function=blue, Keyword=purple, Comment=grey, ...
Alternative: pick by hue like theme/palette.lua (more accurate, more code).
Card width - recommended
Fixed ~42 columns, centered.
Alternative: keep today's 80% width.

Testing

  • Headless: the two new tests plus all existing tests/test-finder-*.lua.
  • Bench: finder benches and bench-ux.sh all; other pickers must not regress.
  • Manual: PM scenarios 1-6, cold vs warm cache, resize while open, swatches survive moving the cursor.

Success criteria

  • ☐ Prompt box above a separate list box; separators between rows only
  • ☐ Ten squares per row in each theme's own colors; editor never repainted by opening
  • ☐ Warm open instant; cold open fills in without blocking
  • ☐ Preview / Esc / Enter unchanged; swatches survive previews
  • ☐ Other pickers unchanged (tests + bench green); stylua clean
