Finder GitHub source: dev spec

Two thin sources, gh_pr and gh_issue, share one factory. They run gh api search/issues with the prompt text as the query and feed the existing live (stream) pipeline. The finder gets four small opt-in capabilities, so live_grep and every other source stay untouched.

PM spec: docs/pm-specs/finder-github-source.md. Five phases, each mergeable alone. Please read "PM spec gaps" first: three places where the approved PM spec does not match what I verified.

How it fits together

Two network paths: the search (on typing) and the detail fetch (on cursor stop). Both are async and cancellable; neither blocks the UI.

PM spec gaps - need your call

1. Invalid qualifiers are not errors on GitHub

Verified: state:opn, state:, foo:bar and an unterminated label:" all return HTTP 200 with 0 results. Only real failures error: 422 (repo not found), 403/429 (rate limit), auth, network. The PM spec promised an error line for a bad qualifier value.

Proposed: keep the error line for real failures, show "No results for this search" for bad qualifiers, and I update PM STATE 5 and scenario 8C to match.

2. The "same count as other pickers" does not exist

The finder has no result count anywhere today.

Proposed: add it (right-aligned in the prompt row, 22/22, 100+ at the cap), opt-in for the GitHub sources, in Phase 2. Alternative: drop the count from the PM spec.

3. <C-s> / <C-v> "do nothing"

Today they close the picker first, then do nothing. Phase 3 adds a guard so the picker stays open for items without a file.

Noticed, not touching: the list-pane <C-v> handler calls open_split instead of open_vsplit. Pre-existing and outside this feature.

Research

  • Reuse: stream pipeline, the source/lsp.lua factory pattern (one factory, one-line instances), input spinner, Toast, Util.debounce, test scaffolding that stubs render/ui.
  • Use: gh api search/issues (one call returns PRs and issues; sort: and author:@me work in q), gh pr|issue view --json for detail, gh auth token --hostname (local, about 60 ms) for the login check, vim.system, vim.ui.open.
  • Build: query builder, API wrapper, preview renderer, and four finder capabilities that did not exist: prompt prefill, keep-old-list, message rows and source preview hook, per-source title/debounce/count.
  • Constraint found: search API allows 30 requests/minute, so GitHub sources use a 400 ms debounce (default live is 200 ms).
  • The snacks reference delegates to its own Api.list, which I did not read in detail. Behavior was checked against gh directly.

Phases

Phase 1: Query and API core risk: medium

Goal: pure, tested logic with no UI. Merges alone.

  1. source/gh/query.lua: tokenizer, build, default_text.
  2. source/gh/api.lua: search via gh api, item normalization (open, draft, merged, closed), error classes, kill().
  3. Tests with stubbed vim.system.

Depends on: nothing.

Phase 2: Finder capabilities risk: high

Goal: generic opt-in features, no GitHub yet. Hot path shared with live_grep, so every new branch is gated on a source flag.

  1. Document new ASource and Item fields.
  2. stream.lua: retain_results (old list stays; first new batch replaces it; zero results clear) and run_when_empty.
  3. Prompt prefill (cursor at end), run once on open, count, title and debounce overrides.
  4. source.check() pre-flight in finder/init.lua.
  5. Tests: retain behavior, prefill, plus all existing finder tests unchanged.

Depends on: nothing (parallel to Phase 1).

Phase 3: Sources, list, actions, keys risk: medium

Goal: usable list in the picker, preview pane off for now.

  1. source/gh.lua + gh_pr.lua/gh_issue.lua: flags, check() toasts (no gh, no remote, not logged in), get with generation guard, message rows for empty/error.
  2. Row format and highlights: state icon colors, number, title, author, label badges.
  3. Enter opens URL, <C-y> copies URL, split keys leave the picker open, message rows ignored.
  4. Keys <leader>ghp / <leader>ghi with preview = false.

Depends on: Phases 1 and 2.

Phase 4: Preview risk: medium

Goal: PM STATE 1 and 2 preview pane.

  1. source/gh/preview.lua + render dispatch: instant header from the list item; detail fills branches, checks, mergeable, changes, description (markdown), conversation; cached per picker; late responses for a moved cursor are dropped. Keys flip to preview = true.

Depends on: Phase 3.

Phase 5: Verification and docs risk: low

  1. Full headless suite, bench-grep.lua, bench-ux.sh all: prove live_grep did not regress.
  2. /update-codemap.

Testing strategy

  • Headless: four new tests (see Files) plus all existing tests/test-finder-*.lua and test-preflight.lua.
  • Bench: scripts/bench-grep.lua, scripts/bench-ux.sh all, compared to numbers before Phase 2.
  • Type check: lua-language-server --check as in DEVELOPMENT.md.
  • Manual: PM scenarios 1 to 9 in this repo (has a GitHub remote). 8A from /tmp, 8B with gh off PATH, 7 by typing fast. Screenshots checked against the PM mockups for row, preview and prompt-row layout.

Success criteria

  • Both keys open pickers pre-filled with the default text, cursor at the end, results shown without typing.
  • List shows the repo's open items, newest created first, with icon, number, title, author, colored labels.
  • Editing the text matches what github.com shows for that text (state, author, label, words, other repo, kind flip, sort:).
  • Preview shows metadata, description, conversation; header instant; revisits instant.
  • Fast typing runs one search; stale responses never overwrite newer ones.
  • Old list stays and a spinner replaces the count during a search; zero results clear the list.
  • Empty results and real errors show one in-list line, never a popup.
  • No remote / no gh / not logged in: toast, no picker.
  • Enter opens the browser, <C-y> copies the URL, split keys keep the picker open, Esc closes cleanly.
  • Technical: all headless tests pass, live_grep bench within noise, luals clean, no vim.notify or lib-config keymaps in new code.
