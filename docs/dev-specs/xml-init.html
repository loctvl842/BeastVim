XML language support: dev spec

New xml.bvim plugin (parser, auto-close tag) plus a small, XML-only addition to the indent scope lib. Parser gives folds and highlighting; the scope finder learns element; > becomes a buffer-local insert mapping.

PM spec: docs/pm-specs/xml-init.md

How it fits together

Phase 1 builds the parser branch, Phase 2 the scope node, Phase 3 the auto-close branch. Each merges on its own.

Research

Repo search

  • No XML code anywhere; parsers.lua has no xml entry and the fallback URL tree-sitter/tree-sitter-xml does not exist. Real grammar: tree-sitter-grammars/tree-sitter-xml, location = "xml", ships parser.c, pinned 5000ae8f.
  • Installer already pulls folds.scm, indents.scm, highlights.scm from nvim-treesitter. Upstream XML folds: element, doctypedecl, Comment.
  • autopairs has no > mapping and no per-filetype scoping.
  • markdown.bvim is the template: FileType + open-buffer loop, buffer-local <Cmd> mapping that calls press, fallback to the previous mapping, stubbed-globals test harness.
  • collect_segments already splits on shallower lines, so finding an element node yields the two expected stretches.

Reuse: parser pipeline, scope segments, plugin template. Build: auto-close analysis, per-language scope types, start-tag anchoring.

Built-in / existing lib check

InsertCharPre cannot edit text safely and fights blink.cmp; autopairs cannot host a per-filetype key. Decision: Use tree-sitter folds, Reuse the markdown plugin pattern, Build the rest.

Decisions for you

1 · Where does element become a scope type?

Recommended: per language, scope_types_by_lang = { xml = { "element" } }. HTML also names its nodes element, so a global entry would change HTML, which the PM spec rules out.
Global entry: one line, but HTML scope drawing changes.

2 · Upstream folds also fold multi-line comments and the doctype

Recommended: accept the upstream query. Same query set as every language, nothing to maintain. The PM rule becomes "elements fold; comments and doctype may too".
Ship a local folds.scm with elements only: exact PM wording, but BeastVim owns a query.

Amendment · a folded element keeps its closing tag

Supersedes decision 2. xml.bvim replaces the folds query for xml (via vim.treesitter.query.set, because a query file would lose to the synced upstream one depending on runtimepath order). element is captured with #offset! @fold 0 0 -1 0 so the fold ends one line early. Elements with nothing between their tags get no fold of their own. Comments and doctype keep the upstream capture. Test: xml.bvim/tests/test-folds.lua.

3 · Auto-close lives in xml.bvim

Recommended: in the plugin. It is XML-only and autopairs has no filetype scoping. The pure function can be lifted out if HTML or JSX want it later.
Extend autopairs: shared, but needs a new per-filetype mechanism first.

4 · Heads up: XML indenting changes too

Upstream indents.scm exists, so BeastVim turns on tree-sitter indenting for XML: o and <CR> indent by element depth. Intended, but not in the PM spec. Say so if you want it off.

Phases

Phase 1 · Parser and folds low

Goal: highlighting and element folds. PM scenarios 1, 5, 6.

  1. Registry entry in parsers.lua.
  2. Scaffold plugin (new-lang conventions, no LSP): ensure_parser("xml"), README, configs, git init.
  3. Register in lang.lua blocked needs BeastVim/xml.bvim to exist on GitHub. Creating and pushing it is yours; until then I verify with the plugin on the runtimepath.

Phase 2 · Element scope medium

Goal: the reported bug. PM scenarios 2, 3, 4, 7. Depends on Phase 1 for the parser, not for code.

  1. Per-language scope types in config.lua and scope/treesitter.lua (set built from the buffer's language, cached per language).
  2. Skip single-line elements: only for per-language types, so other languages keep today's nil-then-indent behaviour.
  3. Anchor body after the start tag when there is no body field, so wrapped attributes are not body.
  4. Tests: reported case (34 gives {34,34} and {36,36}), 35, 33, 37, nested, wrapped tag, broken XML, HTML unchanged.

Phase 3 · Auto-close tag medium

Goal: <class> closes itself. PM scenarios 8, 9.

  1. Pure analysis closing_tag(before, after): scan back at most 50 lines to the last <; collapse quoted values; nil for open quote, existing >, trailing /, </, <!, <?, < b, or an existing closer after the cursor.
  2. Mapping: buffer-local > returning a constant <Cmd>; press reads the buffer at run time, falls back to a plain or previous >, otherwise inserts both tags and steps back with <C-g>U<Left> for one undo.
  3. Attach on FileType plus the already-open buffers.
  4. Tests: all scenario 8 and 9 lines, multi-line start tag, undo, dot-repeat, behind a global mapping and blink.cmp.

Phase 4 · Docs low

  1. /update-codemap, plugin README with install snippet and the new option. No CHANGELOG edits.

Testing

  • Headless: the three indent scope tests, test-autoclose.lua in the plugin, and the lua-language-server --check command from DEVELOPMENT.md.
  • Bench: tests/bench-scope.lua before and after Phase 2 (scope runs on every cursor move); ./scripts/bench-ux.sh all if folds or the statuscolumn are affected.
  • Manual E2E: reproduce first in tmux on complex.xml at 34:12 (expect today's single run), then confirm two runs after. Walk PM scenarios 1 to 9; for scenario 6 delete the installed xml parser and reopen. Check sign position, element line column and closed-fold glyph by eye.

Success criteria

  • No fold sign on 34, 35, 36; signs on 32 and 33 and every other multi-line element.
  • Cursor 34:12: element line on 34 and 36, not 35; debug() lists both stretches at col=6, indent=8.
  • Cursor on 35, 33 or 37 marks the annotation element.
  • zc inside an element folds everything between its tags; the opening and closing tag stay visible.
  • First open without the parser works without restart.
  • Missing closing tag: no errors, complete elements still fold and mark.
  • Auto-close behaves per scenarios 8 and 9; one undo reverts both.
  • HTML and existing indent scope tests unchanged; scope bench shows no regression.
  • Type check passes.
