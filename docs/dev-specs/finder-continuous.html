Continuous finder - dev spec

The finder keeps its three windows and swaps what they show: a level stack inside the one picker state. <C-g> asks the current source for its next level and pushes; <BS> on an empty prompt or <C-o> pops back with no re-search. Scoped grep is the existing grep source given a file list. Files and Buffers rows are restyled first, because the chain depends on that look.

PM spec: docs/pm-specs/finder-continuous.md (approved). Source of truth for implementation: docs/dev-specs/finder-continuous.md.

How it works

Source opt-in

source.drill = { hint(total, selected) -> string?, open(ctx) -> spec | toast-string | nil }, where ctx.items is the full match set (nil while still working). Refused with a toast while loading, empty, or no drill.

Why the full match set needs work

The fuzzy matcher keeps only the top 1000 matches for display. The scope for "grep these files" must be all of them, so the matcher's score table (already built for subset elimination) is used: matches(state) = items with score > 0, count(state) = a counter added to the final pass (O(1) per item, benched).

Phases

Each phase is mergeable and verified on its own. Phase 1 changes how normal Files/Buffers look.

Phase 1 - Row look prerequisiterisk: medium

  1. Extract file_row (icon, base, dim dir, src ranges) from live_grep_header; the header calls it unchanged.
  2. format.filename and format.buffers use it; [+] kept at the end, [n] dropped.
  3. match_hl maps match positions through src ranges (base, dir, boundary, trimmed dir).
  4. Tests: test-finder-format.lua, test-finder-match-hl.lua; fix any old row assertions.

Phase 2 - Chain core + Files to grep risk: high

  1. Matcher total; match.count/matches; count label after each settled run; title refresh on load.
  2. Stream count/matches and empty-prompt placeholder row.
  3. State stack: closure uses instance.query/pipeline; push/pop in place; reset cleans stacked queries.
  4. ui/input.set_text (echo skip, no double search).
  5. ui/hint.lua: borderless, non-focusable float under the frame, right-aligned, hidden when no room, backdrop-matched colors.
  6. chain.lua + keys: <C-g>, <C-o>, <BS> as an expr mapping (pop only when the prompt is empty).
  7. Scoped live_grep (filter.files as survivors) and its placeholder.
  8. files.drill + count.
  9. Tests: test-finder-chain.lua, test-finder-chain-grep.lua (incl. >1000 matches).

Phase 3 - Buffers and Help to grep risk: low

  1. buffers.drill (nameless skipped), help_tags.drill (distinct help pages), counts.
  2. Test: test-finder-chain-sources.lua.

Phase 4 - Pull requests to Files Changed risk: medium

  1. api.files: gh api repos/{slug}/pulls/{n}/files, up to 3 pages of 100, truncation flag, error classification, killable.
  2. gh_pr_files source: match pipeline, fuzzy by path, title PR <title...> › Files Changed (N), diff preview from patch ("too large or binary" when absent).
  3. action: Enter opens the file's diff in a read-only scratch buffer.
  4. PR drill in gh.lua; tests: test-finder-gh-files-api.lua, test-finder-gh-pr-files.lua.

Phase 5 - PR files to grep (local copies) risk: low

  1. gh_pr_files.drill: drop removed and non-existing paths; none left means a toast; title N PR Files › Live Grep.
  2. Test: test-finder-chain-pr-grep.lua (three-level back chain).

Phase 6 - Issues to grep risk: medium

  1. Keep issue body in normalize.
  2. gh_issue_grep live source (title + body lines), grouped by issue via item.group or item.file in ui/list.lua, header format, preview, Enter opens the URL, gh_issue drill.
  3. Test: test-finder-gh-issue-grep.lua; existing grouping/separator tests must stay green.

Phase 7 - Docs and wrap-up risk: low

  1. Codemap (libraries.md, INDEX.md), dev spec Completed section, final verification.

Decisions for you

Swap levels in place (keep windows, replace query/pipeline) rather than close and reopen the picker for each level. No flicker, backdrop stays, parent keeps its results so back is instant and makes no GitHub call. Cost: a careful refactor of the picker state (Phase 2, the one high-risk step). Recommended
Show a match count (38/912) in the prompt row for Files, Buffers and Help. The approved mocks show it and the hint needs the number anyway. This is a small visible change to those pickers. Recommended
<C-o> in insert mode becomes "back" inside the finder prompt (it is normally "one normal command"). Nothing in the finder uses it today. Recommended
Scoped grep skips the bigram index and greps the given files directly (batched, killable). Large scopes (whole project) are slower than the indexed path; an optional follow-up can intersect with the index. Recommended for v1

Testing

  • Headless: new tests/test-finder-*.lua per phase plus all existing finder tests; stylua and luals clean.
  • Bench: bench-finder-matcher.lua before/after Phase 2; bench-ux.sh all against a baseline worktree.
  • Manual in a real wezterm pane: PM scenarios 1-13 and STATE 0, hint in dark and light, short terminal height.
  • Not testable offline: live GitHub paging beyond stubs, browser open, clipboard (reported at the end).

Success criteria

  • Files and Buffers rows: icon, name, dim folder; [+]; fuzzy highlight correct.
  • Files, Buffers, Help <C-g> greps only the matching files, also with more than 1000 matches.
  • PR <C-g>: changed files with diff preview, filter by path, 300 cap with "(partial)".
  • PR files <C-g> greps local copies; Issues <C-g> greps title and description.
  • <BS> (empty prompt) / <C-o> restore prompt, results, row with no new search.
  • <Esc> closes the whole chain; Enter closes it too.
  • Titles and below-the-frame hint as in the PM spec; hidden when no room.
  • Refusals toast and change nothing; windows never close and reopen on push/pop.
  • Technical gates: tests, luals, stylua, benches at baseline, Toast and packer.lazy conventions.
