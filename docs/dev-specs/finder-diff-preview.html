Finder diff preview - dev spec

The repo already has a rich diff renderer (the git hunk float) and four raw-text diff paths in the finder. A second renderer for the new look would duplicate the first, so the work starts with two behavior-preserving refactors, then the feature on top:

  1. Lift the row renderer out of git/preview.lua into a shared view/diff.lua.
  2. Give the finder one place for a file's patch, its summary and the "binary" placeholder, and one scratch-buffer opener.
  3. Draw Files Changed (and commits) with the shared renderer. Syntax coloring last.

PM spec: docs/pm-specs/finder-diff-preview.md (approved)

Duplication found

  • The renderer: render_rows, apply_decorations, _statuscol, the gutter window options, the red/green groups and word_spans are all locked inside the git lib. The finder needs the same thing; copying makes two.
  • Finder, 3x each: vim.split(patch, "\n") and the text "(diff too large or binary)" (gh_pr_files, commit_preview.build, action.open_diff); a file's summary line in two formats (head, file_line).
  • Scratch buffers: open_diff and open_commit repeat ~12 lines.
  • Pane writes: gh_pr_files.preview and commit_preview.draw repeat modifiable / lines / filetype / loaded_file / title / cursor.

Target structure

Research

  • Reuse, mostly: the whole renderer exists. The work is moving it to a neutral place and making it serve two callers.
  • Why view/: it is already the shared UI toolkit (view/buf, view/win). Groups follow Beast<Lib>* as BeastViewDiff*; hl_reload.lua needs one registry line. BeastGitPreview* is used only in git/preview.lua and git/highlights.lua, so renaming is safe.
  • Gutter store: a module-local weak table keyed by buffer, not vim.b (a read copies a Vimscript dict, once per screen row; fine for a hunk, bad for 3000 rows).
  • Wrapping: the statuscolumn is called per screen row with v:virtnum > 0 on continuation rows: one branch blanks the numbers.
  • Enter must stay raw: commit_preview.build feeds the pane and Enter's buffer; it keeps its output.
  • Tests touched: test-git-preview (_test.render_rows), test-git-word-diff, and the four finder preview tests.

Decision Reuse (move the git renderer + word spans to view/diff.lua) + Build only the finder adapter. No new dependency.

Shared row model

row = { kind = text|head|gap|hunk|code|note, text, old?, new?, sign, spans?, marks? }
render(rows, { columns = 1 | 2 }) -> { body, hls, spans, gutters, width }

columns = 1  git float:   source line number + mark
columns = 2  finder:      old  new  mark
wrapped screen row (v:virtnum > 0) -> blank gutter in the row's tint
non-code rows (head, gap, hunk, note) -> blank gutter in their own background

finder gaps: above first hunk = new_start - 1
             between hunks   = next.old_start - (prev.old_start + prev.old_count)
             nothing after the last hunk (a patch does not carry the file length)

Phases

Phase 1 - Shared renderer, git hunk preview migrated refactor, nothing looks different

Depends on: nothing. Proves the shared code by serving its original caller first.

1. Baseline LowRun tests/test-git-* and tests/test-finder-*; screenshot the git hunk preview (staged, unstaged, changed words).
2. Shared highlights Lowview/highlights.lua + registry line: BeastViewDiff* (same blends), plus LineNr, Hunk, Gap, Head. git/highlights.lua keeps blame, conflict, staged badge.
3. view/diff.lua MediumMove word_spans out of git/diff.lua; add pair; move render_rows (with columns), apply_decorations as paint/clear, _statuscol as statuscol (weak table), gutter window options as attach/detach. Risk: statuscolumn registration, width, extmark priorities must stay identical.
4. Migrate the git float Mediumgit/preview.lua calls view/diff; keeps build_rows, placement, close wiring.
5. Tests Lowtest-view-diff.lua (moved word-span cases, columns = 2, wrapped-row gutter, non-code rows); git tests only change imports; baseline comparison; bench-git.lua before/after.

Phase 2 - Finder dedupe refactor, nothing looks different

Depends on: nothing (can run in parallel with Phase 1).

1. One place for a file's patch Lowfinder/ui/diff.lua: summary(file) (one format), raw_lines(file) (patch lines or the single placeholder definition).
2. Use it Lowgh_pr_files.preview, commit_preview.build/file_line, action.open_diff; add open_scratch for open_diff and open_commit. The four finder preview tests pass unchanged.

Phase 3 - Draw Files Changed with the shared renderer the feature

Depends on: Phases 1 and 2.

1. Patch to rows Mediumparse (hunks, no-newline note, CRLF) and rows: head row with +/- bar, gap, hunk, code rows with old/new numbers, pair for word spans, placeholder row, MAX_ROWS = 3000. Risk: header edge cases (-0,0, +1,0, omitted counts).
2. draw / leave MediumWrite buffer, render(columns = 2), paint, attach, then wrap = true, filetype = "", title, cursor row 1. leave detaches and restores wrap = false. Risk: shared preview window; width must not flicker.
3. Wire Files Changed Lowgh_pr_files.preview draws via ui/diff; commit and local-commit Files Changed follow (aliased). Enter untouched.
4. Release the window Mediumdiff.leave(view) in ui.preview.show/clear/draw_image and gh/preview.show. Risk: a writer that forgets leaves a stale gutter.
5. Tests Lowtest-finder-diff.lua (two hunks gap 13 / 19 above, pure add, pure delete, rename, no patch, spans, cap, no-newline, CRLF) and picker tests (gutter via nvim_eval_statusline(use_statuscol_lnum), wrapped row blank, <BS> restores window options, Enter still raw).

Phase 4 - The commit preview uses the same look

PM decision 3. Depends on: Phase 3.

1. Styled sections Mediumcommit_preview.lua: local summary() shared with build (Enter stays raw); pane = text rows + head row and diff.rows per file. Early draw (no detail yet) must work.
2. Tests Lowgh-commits and git-commits expectations; Enter still a raw diff buffer.

Phase 5 - Syntax coloring

PM decision 2. Depends on: Phase 3. Can be dropped without affecting the rest.

1. Per-side treesitter MediumParse each hunk's old side (context + removed) and new side (context + added) separately with get_string_parser; fg-only capture extmarks through the shared paint. Skip on too many rows, long lines, no parser, any error. The git float keeps its whole-buffer parse.
2. Tests Lowcaptures on code rows only; unknown extension and oversized file draw plain; time a 3000-row draw.

Testing

  • Headless, after every phase: tests/test-view-diff.lua and test-finder-diff.lua (new), all tests/test-git-*.lua, all tests/test-finder-*.lua.
  • Types and style: lua-language-server --check . --checklevel=Warning, stylua.
  • Bench: scripts/bench-git.lua before/after Phase 1 (hunk preview is on its path); bench-ux.sh all before merging Phases 1, 3 and 5; time draw on 3000 rows.
  • Manual: Phase 1: git hunk preview identical to the baseline screenshot. Phases 3-5: PM scenarios 1 to 9; hold <Down>, resize with a long line open, <BS> to PRs and to a grep, :colorscheme light and dark, deleted and binary files; pixel-level check of gutter and tint continuity across wrapped rows.

Success criteria

  • After Phases 1-2 nothing looks different and all tests are green.
  • One implementation of rows-to-buffer, word spans, tints and gutter, used by the git float and the finder; one source of red/green groups.
  • One definition in the finder of: the "binary" placeholder, a file's summary line, splitting a patch, opening a scratch diff buffer.
  • All PM spec criteria (header, numbers, red/green, changed words, wrap, gaps, special files, commit preview, colorscheme, speed, keys unchanged).
  • Code colored for the file's language without breaking tint or word backgrounds.
  • After leaving a diff the pane has no gutter, and file previews have line numbers again.
  • Git and finder tests, type check, bench-git.lua and bench-ux.sh all healthy.

Needs your eye

Where the shared renderer lives

Recommended libs/view/diff.lua with BeastViewDiff* groups: view/ is already the shared UI toolkit and the renderer also paints buffers and sets window options.
Alternative util/diff.lua: rejected, util has no UI code today.

PM spec gap, scenario 8

The PM spec says "the finder keeps its own colors while open". In the code only the prompt and list panels are frozen; the preview uses global groups, so the diff recolors with :colorscheme. This plan implements "recolors". The second sentence of scenario 8 should be dropped from the PM spec - say if you want it edited.

Scope

Phases 1-2 are the refactors you asked for before new features. Not touched: the review lib's inline overlay, git/patch.lua, and moving the git float to the finder's per-side syntax parse.
