Markdown lists - dev spec

A new standalone BeastVim/markdown plugin (same shape as json, python, cpp) that continues, numbers, nests and exits markdown lists. Enter and Tab are expr mappings that return a constant <Cmd>; the decision runs when it is consumed (works with queued keys and behind blink.cmp) and feeds keystrokes, so splitting, autoindent and undo behave like normal typing; outside a list they fall back to the previous mapping (autopairs, blink).

PM spec: docs/pm-specs/cross-markdown-lists.md (approved). Plugin repo: neovim_plugins/markdown.

Context

Problem. BeastVim has language plugins for code only. Markdown has highlighting (render-markdown) and fence expansion (autopairs), but nothing understands list structure.

Solution. A markdown plugin whose buffer-local mappings parse the current line and either return the keys that make the next item or hand off to the previous mapping.

How Enter flows

Research

Repo search

  • Searched: markdown, <CR>, <Tab>, lang.lua, sibling plugins, Key.safe_set, blink and autopairs keymaps.
  • Found: language plugins are standalone repos loaded on filetype; autopairs owns a global insert <CR> (fence expansion); blink uses preset "enter" and falls back when the menu is closed; Key, Treesitter, Toast globals exist; no list code anywhere.

Built-ins

  • formatoptions r/o only continues comment leaders: no numbering, no un-nest, no checkbox reset.
  • Decision: Build a small pure-Lua module on Used Neovim APIs and Reused Key, Treesitter, scaffold pattern.

Implementation phases

Phase 1 - Plugin + Enter continuation medium

Goal: bullets, ordered (next number), tasks, empty-item exit, mid-item split, fence guard. Mergeable alone.

  • Scaffold the repo (README, stylua, luarc), git init, no commit.
  • list.lua: parse quote prefix, indent, marker, checkbox, offset, empty flag; next_marker.
  • actions.enter() + in_fence: returns <C-g>u<CR> + typed marker; one undo step, autoindent-safe. autoindent doubling
  • Fallback: capture the global <CR> (autopairs) at install and call it when not in a list. ordering with blink
  • setup(): guard, ensure_parser x2, FileType mapping via Key.safe_set, add the lang.lua entry (local path while developing).
  • Tests for scenarios 1, 3, 4, 5 (step 1), 6, 7.

Phase 2 - Numbering and nesting medium

Goal: renumber, Tab, Shift-Tab, un-nest on empty item. Depends on phase 1.

  • renumber(row): same indent + ordered kind, skips deeper lines, stops at shallower item; runs via <Cmd> in the same undo block.
  • Tab / Shift-Tab on list items; restart at 1 when nesting; fall back for pum, snippets, non-list lines.
  • Enter on an indented empty item acts as Shift-Tab; unindented clears the marker.
  • Tests for scenarios 2, 5 (step 2), 8 and the one-undo rule.

Phase 3 - o / O and integration medium

Goal: normal-mode continuation and real-UI checks. Depends on phase 2.

  • o / O buffer-local; off a list they return the plain key.
  • Block quote prefix E2E tests (> - item).
  • Manual: blink menu + Enter, fence expansion, snippet Tab, render-markdown, non-markdown startup unchanged.

Decisions for you

1 - Nested indent width

The PM spec examples show 4 spaces for a nested ordered item; CommonMark needs the parent's content offset (2 for - , 3 for 1. ), and shiftwidth is 2.

Parent content offset (recommended). Always renders as nested. PM examples (scenario 8, state 5) would show 3 spaces.
Fixed 4 spaces. Matches the PM examples literally; bullets under bullets would be 4 deep.

2 - Keymap registration

Key.safe_set with buffer from a FileType autocmd (recommended). The plugin is external and the keys are filetype-local.
packer.lazy keys with a filetype condition. Only if the packer supports it; needs checking.

3 - Tests location

Inside the plugin repo (recommended). Self-contained.
BeastVim/tests/. Follows the repo test convention; needs the plugin path on the runtimepath.

4 - Fence detection

Line scan for fence openers (recommended). No parser dependency, works while typing.
Tree-sitter fenced_code_block. More exact, depends on a fresh parse.

Testing strategy

  • Headless: tests/test-lists.lua in the plugin repo via NVIM_APPNAME=BeastVim nvim --clean --headless -l; buffer cases drive the real mappings with nvim_feedkeys.
  • Bench: none needed (markdown buffers only); run the component benches loop and bench-startup.sh once to confirm no regression.
  • Manual: PM scenarios 1-9 in a real markdown file under NVIM_APPNAME=BeastVim, plus the Phase 3 integration checks.

Success criteria

  • Enter on -, *, + items continues with same marker and indent
  • Enter on 1. / 1) gives the next number; following items renumbered
  • Task items continue with an unchecked box
  • Empty item exits the list (or un-nests one level)
  • Enter mid-item splits text into the new item
  • Tab / Shift-Tab nest and un-nest with correct numbering
  • o / O continue the list
  • No change in code blocks, paragraphs, or non-markdown files
  • Completion menu and autopairs keep working with Enter
  • Lazy load with no startup cost elsewhere
  • One u reverts a whole Enter (line, marker, renumbering)
  • stylua --check and tests/test-lists.lua pass
