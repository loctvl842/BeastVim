Select menu: theme-picker look

The select menu (code actions and every other pick-from-a-list prompt) takes on the theme picker's look: a roomy prompt panel (heading + filter line) over a darker list panel, dashed lines between options, and the selected option framed by solid blue lines. Behavior is unchanged.

Problem

Today it is a bordered box: title cut into the border, a "Search" label, a divider before the footer and a bullet marker. It reads heavy and busy, and does not match the theme picker's calmer, more spacious design.

Why now: it is the most frequently seen list menu (every code action), so it should match the new quality bar.

Scenarios

1 - Choosing a code action
  1. Trigger a code action
    Prompt panel with the heading and empty filter line; list panel with the first action framed by solid lines.
  2. Press Down
    Frame, blue text and pointer move to the next option.
  3. Press Enter
    Panels close, action runs as before.
2 - Filtering a long list
  1. Type "drac"
    List narrows; frame and pointer on the first match.
  2. Delete the letters
    Full list returns.
3 - Tags and extra footer hints
  1. Open a branch-style menu
    Dim right-aligned tags; extra hint listed after Confirm and Cancel.
4 - No matches (edge)
  1. Type a query matching nothing
    "No matching items" centered; Enter does nothing.
5 - Cancel
  1. Press Esc
    Panels close; caller gets no selection.
6 - Long labels, narrow terminals (edge)
  1. Label longer than the panel
    Shortened with "..."; pointer and footer never overlap text.

Behavior rules

  • Only the look changes; all behavior and every existing caller stay as today.
  • Same visual language as the theme picker: borderless panels, prompt lighter than list, dashed separators, solid blue frame lines, blue bold text plus pointer on the selected option, no tint.
  • Heading in a warm accent colour, only when the caller gave a prompt; filter line shows only a cursor when empty.
  • Footer hints dim and right-aligned on the list panel's last line.
  • Position, width and the dimmed backdrop are unchanged.

Success criteria

  • ☐ Lighter padded prompt panel over a darker list panel; no borders or divider
  • ☐ Dashed lines between options
  • ☐ Selected option: solid blue frame, blue bold text, pointer, no tint
  • ☐ Footer dim, right-aligned, including caller hints
  • ☐ Tags right-aligned; long labels shortened, no overlap
  • ☐ Empty state shown when nothing matches
  • ☐ Behavior unchanged, headless fallback intact

Out of scope

  • Restyling confirm, input or other menus (possible follow-up)
  • New features: groups, multi-select, previews
  • Changing position or width
