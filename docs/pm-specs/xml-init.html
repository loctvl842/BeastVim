What is wrong today

  
BeastVim does not know XML. It guesses structure from indentation, and one line indented differently (line 35) derails both guesses.

  

    

      Folds
      
Signs sit on the first line inside an element, not its opening tag, and land on text lines (34, 36). One stray line splits one element into several folds.

    

    

      Element line
      
Drawn only around the cursor, stops at the first differently indented line. Line 36 is missing.

    

  

  

    Typing
    
Every element is typed twice. Writing <class> means also typing </class> by hand, and forgetting it leaves the file broken.

  

  
Why now

  
Every other shipped language has its own small plugin. XML is the odd one out. A language plugin is where XML-aware folds and element line belong, instead of special cases in the editor core.

Behavior rules

  
    
    
  • A fold sign appears only on the opening tag line of an element that has at least one line between its tags.
    • 
    
  • A fold covers everything between one element's tags, never a slice of its text. The opening and closing tag lines are never hidden by that element's own fold.
    • 
    
  • The element line is drawn at the indentation of the opening tag, so uneven body text never moves it.
    • 
    
  • It is drawn on each stretch of the body indented at least as deep as the first body line. A shallower line breaks the stretch and gets no line. Two stretches in one element are both drawn.
    • 
    
  • A blank line inside a stretch does not break it.
    • 
    
  • Cursor on a single-line element: the nearest enclosing multi-line element is marked.
    • 
    
  • Opening tag, closing tag or body all mark the same element.
    • 
    
  • Nested elements: the innermost multi-line element around the cursor is marked.
    • 
    
  • Auto-close fires only when > is typed (not on paste), only for an opening tag, and the closing tag uses the exact name, prefix included (app:label).
    • 
    
  • After auto-close the cursor sits between the tags, so one undo removes both the > and the added closing tag.
    • 
    
  • XML dialects with their own file types (schemas, stylesheets, SVG) are not part of the first cut.
    • 
    
  • The plugin works only inside BeastVim and says so plainly when loaded elsewhere.
    • 
  






  
Success criteria

  
    
    
  • In complex.xml, no fold sign on lines 34, 35 or 36.
    • 
    
  • Fold signs on 32 and 33, and on every other multi-line element.
    • 
    
  • Cursor at 34:12 draws the element line on 34 and 36, not on 35.
    • 
    
  • Scope report for that position lists two stretches (34 to 34, 36 to 36), both at column 6, body indent 8.
    • 
    
  • Cursor on the single-line element (line 35) marks the enclosing element.
    • 
    
  • zc inside an element folds everything between its tags and leaves both the opening and the closing tag visible.
    • 
    
  • First open on a clean machine works without a restart once support is fetched.
    • 
    
  • A file with a missing closing tag opens without errors.
    • 
    
  • <class then > gives <class>|</class>, cursor between the tags.
    • 
    
  • <app:label key="team" then > closes with </app:label>.
    • 
    
  • Self-closing tags, closing tags, comments, declarations, doctypes and a > inside quotes add nothing.
    • 
    
  • One undo reverts the > and the added closing tag together.
    • 
    
  • No regression in other languages' fold signs and element line.
    • 
  






  
Out of scope

  
    
    
  • Language server (diagnostics, completion, hover, schema validation). Deferred: the reported problems do not need one, and it adds a download and settings to decide.
    • 
    
  • Formatting on save. Deferred with the language server.
    • 
    
  • XSD, XSLT, SVG and other dialects with their own file types.
    • 
    
  • Tag renaming (editing an opening tag does not rename its closing tag). Deferred: separate from the reported problems.
    • 
    
  • Pressing Enter between the tags to open an indented body line. Deferred: not asked for.
    • 
    
  • Changes to how other languages draw folds or the element line.
