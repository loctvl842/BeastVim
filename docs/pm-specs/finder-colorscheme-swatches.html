Theme picker with color swatches

The theme picker (<leader>c) shows each theme as a roomy row with ten color swatches on the right, so you can judge a palette at a glance. The prompt sits in its own box above the list.

Swatch colors in the mockups below are illustrative.

Problem

Today the picker is a dense list of names. To see what a theme looks like you must step onto it and watch the editor repaint, one theme at a time. Comparing dozens of themes means a lot of key presses and remembering what you just saw.

Why now: live preview already exists. Swatches let you skip clearly wrong themes without stepping through them, and make the picker feel like a gallery.

Scenarios

1 - Browse and pick a theme
  1. Press <leader>c
    Prompt box and list appear; every row already shows its swatches.
  2. Press Down a few times
    Highlight moves; the editor repaints in each theme.
  3. Press Enter on ayu_dark
    Picker closes; editor stays in ayu_dark.
2 - Cancel restores the original theme
  1. Press <leader>c in monokai-pro
  2. Move onto ayu_light
    Editor turns light.
  3. Press Esc
    Picker closes; editor returns to monokai-pro.
3 - Filter by name
  1. Type ay
    Only matching themes remain, each with swatches.
  2. Press Enter on the top row
    That theme is applied.
4 - Theme with unreadable colors (edge)
  1. A theme lacks some colors the strip needs
    Missing squares are dim grey, so the strip is always ten wide and rows stay aligned.
5 - Long name / narrow window (edge)
  1. Open in a narrow terminal, or with a very long name
    The name is shortened with ... so swatches are never pushed off or overlapped.
6 - Empty filter result
  1. Type zzzz
    List box shows no rows; Enter does nothing.

Behavior rules

  • Always ten squares in a fixed order, so a column means the same role across themes.
  • Proposed order: background, foreground, red, orange, yellow, green, cyan, blue, purple, grey.
  • Swatches show each theme's own colors; opening the picker never changes the theme by itself.
  • All rows show swatches at once, and opening is not slower than today.
  • Live preview and restore-on-cancel behave exactly as today.
  • Order, filtering, selection keys and the starting row (top) unchanged; only the look changes.
  • Only the theme picker changes; files, buffers, grep and help pickers keep their look.
  • Preview pane stays off for the theme picker.
  • Dashed separators between rows; the selected row is framed by solid lines above and below (also at the top and bottom edges); no background tint.

Decisions for you

Visual change only. All behavior stays as today (checked against the current picker).

Swatch roles - recommended
bg, fg, red, orange, yellow, green, cyan, blue, purple, grey. Comparable column by column.
Alternative: the theme's ten most frequent accent colors (varies per theme, less comparable).

Success criteria

  • ☐ Borderless prompt panel above a darker list panel
  • ☐ Name left, ten colored squares right, on every row
  • ☐ Dashed line between rows; selected row framed by solid lines, blue text and a pointer
  • ☐ Squares match the colors the theme really uses
  • ☐ Swatches visible immediately on open, no delay
  • ☐ Live repaint, Enter keeps, Esc restores
  • ☐ Filtering keeps swatches
  • ☐ Missing colors show dim grey; always ten squares
  • ☐ Long names shortened, never collide with swatches
  • ☐ Other pickers look unchanged

Out of scope

  • Same look for other pickers (possible follow-up)
  • Sample-code preview pane (live repaint covers it)
  • Editing or creating themes
  • Sorting or grouping dark/light
  • Active-theme badge (can be added later)
