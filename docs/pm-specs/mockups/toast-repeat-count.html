Toast repeat count

When the same toast fires again while it is still on screen, it does not stack another line. The existing one gains a count: x2, x3 ... xN. Try the buttons below.

Try it

Each toast stays 2.2 s, like today. A repeat restarts that timer, so a message that keeps repeating stays visible and keeps counting. After it disappears, the next occurrence starts again at no count.

Questions for you

  • Which messages count as the same? I assumed the same text, same level and same title. "Pattern not found: foo" and "Pattern not found: bar" stay separate.
  • Not only consecutive. If "A", then "B", then "A" arrive while all are visible, should the second "A" go to the first "A" (x2) or become a new line? The demo merges it into the first.
  • Timer. A repeat restarts the 2.2 s timer. OK, or should the first appearance time still decide when it goes away?
  • Wording. x2 after the message, in the accent color, as in the mockup. The existing progress toasts use (2). Align them to x2 too, or leave progress alone?
  • Cap. Show x99+ from 100 onward?
  • Sticky toasts. Toasts with no timeout (progress, loading) are not merged, to keep their in-place updates. OK?
