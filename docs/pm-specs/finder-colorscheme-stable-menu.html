Stable theme menu

While you browse themes, the picker menu keeps the colors of the theme you started with. Only the editor behind it previews the highlighted theme, and it is no longer dimmed.

Problem

Every step down the list repaints the whole screen, menu included: panel colors, text, selection color and lines all change per theme. It is hard to tell what the menu normally looks like, and judging a theme while the menu keeps changing is confusing. The dimming overlay also darkens the editor you are trying to preview.

Target behavior

STATE 1 - Opened in monokai-pro

 
monokai-pro
ayu_light
bearded-arc

Editor at full brightness, no dimming. Menu in monokai-pro colors.

STATE 2 - Navigated to ayu_light

 
monokai-pro
ayu_light
bearded-arc

Editor behind is fully ayu_light (light). The menu panels, text, lines and selection color are STILL monokai-pro. Swatches keep each theme's own colors.

STATE 3 - After Enter, reopened

The menu now uses ayu_light's colors: it takes on the new theme the next time it opens.

Scenarios

1 - Browse themes, menu stays put
  1. Press <leader>c in monokai-pro
    Menu in monokai-pro colors, no dimming overlay.
  2. Press Down through light and dark themes
    Editor repaints each time; the menu keeps its monokai-pro colors.
2 - Confirm a theme
  1. Enter on ayu_dark
    Menu closes, editor is ayu_dark.
  2. Open the picker again
    Menu now in ayu_dark colors.
3 - Cancel restores the original theme
  1. Navigate, then Esc
    Menu closes; the editor returns to the theme from when it opened.
4 - Filtering and scrolling (edge)
  1. Type "mono", scroll a long list
    Match highlights, selection, separators and swatches keep the menu's colors.
5 - Resizing while open (edge)
  1. Resize the terminal while previewing another theme
    Menu re-lays out and keeps the original theme's colors.

Behavior rules

  • Menu colors are fixed when the picker opens, until it is closed and reopened.
  • Everything outside the menu (editor, statusline, tabline) previews as today.
  • Swatches always show their row's own theme colors.
  • Fuzzy-match highlights keep the menu's colors.
  • Preview, Esc restore and Enter apply behave as today.
  • Theme picker opens without the dimming overlay; other pickers keep theirs, colors unchanged.

Success criteria

  • ☐ Menu does not change colors between a dark and a light theme
  • ☐ Editor still previews at full brightness (no overlay)
  • ☐ After Enter, reopening shows the menu in the new theme
  • ☐ Esc restores the original theme
  • ☐ Filter highlights, selection and swatches correct while previewing
  • ☐ Other pickers unchanged, including their overlay

Out of scope

  • Making other pickers immune to theme changes (they never change the theme)
  • A sample-code preview pane
  • Changing the menu design itself
