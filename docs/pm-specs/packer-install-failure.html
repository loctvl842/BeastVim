PM spec · 2026-11-11

packer-install-failure

When one plugin cannot be downloaded, the rest of BeastVim must still start fully, the user is told once, and later starts do not pay for retrying the download every time.

Problem

  • Setup stops half-way. Plugins that did download are present, but the remaining startup work is skipped. Settings, keymaps and features silently go missing.
  • Every start is slow. The broken download is retried on every launch and blocks the editor, about 300ms per broken plugin.
  • The error is a raw message instead of the usual BeastVim toast, and is easy to lose.

Seen for real: three language plugins were private, CI could not download them, and startup read ~330ms instead of ~40ms for weeks, on a partly set-up config.

Target behavior

State 1 · first start, plugin unreachable 
editor opens normally, everything else works

                 ┌─────────────────────────────────────┐
                 │  ⚠ Could not install "json"         │
                 │    repository not found or no       │
                 │    access. Skipped for now.         │
                 └─────────────────────────────────────┘

One toast, once. All other plugins load and are configured as usual.

State 2 · later starts, inside retry window 
(no toast, no delay)  Packer window:

  ✗ json    install failed 2h ago - repository not found
  ✓ python
  ✓ cpp

Not downloaded again. Listed as failed so the user can see why a feature is missing.

State 3 · retry succeeds 
Packer window after install/sync:

  ✓ json    installed

Failure record cleared; plugin works from next start (immediately if lazy).

Scenarios

1 · One plugin unreachable happy path 
1. Start BeastVim; "json" cannot be downloaded.
   Editor opens. One warning toast names "json", says skipped.
2. Open a Lua file and a Python file.
   Settings, keymaps, language support of other plugins all present.
3. Open a JSON file.
   Only JSON extras missing. Basic editing works.
2 · Next start does not retry 
1. Quit and start again shortly after.
   As fast as with no broken plugin. No toast.
2. Open the Packer window.
   "json" shown failed with reason and age.
3 · User fixes the cause and retries 
1. Make the repo reachable, run install/sync in the Packer window.
   Downloads. Failed marker disappears.
2. Start BeastVim again.
   "json" loads like any other plugin.
4 · Retry window expires 
1. Enough time has passed.
   Next start tries the download once more.
2a. Succeeds -> normal "installed" notice, marker cleared.
2b. Fails   -> recorded again, toast once, window restarts.
5 · Several plugins fail 
Two plugins cannot be downloaded.
One toast lists both names. Everything else loads normally.
6 · Offline start edge 
1. Start with no network, plugins already installed.
   Nothing attempted. No toast, no delay.
2. A brand-new plugin was added to config, never downloaded.
   Reported failed once; the rest of the config loads.

Behavior rules

  • A failed download never stops other plugins from loading and being configured.
  • Reported with the usual BeastVim toast, once per failure; several failures in one start are combined into one toast.
  • A failed plugin is not downloaded again until the retry window ends or the user explicitly retries.
  • The failure record survives restarts.
  • Install/sync/update in the Packer window always retries and clears the record on success.
  • Removing the plugin from config, or changing its source, clears its record.
  • The Packer window shows failed plugins distinctly from not-yet-installed, with reason and age.
  • Already-installed plugins are never affected by another plugin's failure.

Success criteria

  • With one unreachable plugin, every other plugin still loads, settings and keymaps present.
  • A single toast names the failed plugin on first start; none later inside the window.
  • Startup with a known-broken plugin is as fast as without it.
  • The Packer window lists the failed plugin with its reason.
  • Install/sync in the Packer window retries and clears the failure on success.
  • Several failures in one start produce one combined toast.
  • No raw error message for a download failure.

Out of scope

  • Automatically fixing the cause (access, mirrors, credentials).
  • Background retry while the editor is open - the explicit action covers it.
  • Plugins that download fine but crash while loading.
  • CI install changes - fixed separately.
